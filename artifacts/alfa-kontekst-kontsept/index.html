Хакатон Альфа-Банка · трек КИБ

Новостная аналитика, которая знает вашего клиента

Одна лента банка. Шесть разных брифингов. RM открывает стол покрытия и за четыре минуты знает, что сказать CFO — и какой продукт КИБ положить на стол.

Это концепт решения «Альфа Контекст»: зачем оно, как устроен скоринг, кто что делает в команде из пяти человек и как выложить страницу на GitHub Pages или Netlify.

1. Идея

Трек формулирует задачу так: учесть контекст конкретной компании и превратить поток новостей и аналитики Альфа-Банка в персональные инсайты о рисках, возможностях и событиях.

Универсальный саммаризатор эту задачу не закрывает. Новость про CBAM ЕС одинаково «про сталь» для всех — но для Северстали это удар по европейскому нетбэку и повод структурировать ESG-linked RCF к встрече 2 октября, а для X5 это шум с релевантностью около 10.

Не делаем

Ещё одну ленту. Короткий пересказ. «ИИ-помощника», который не знает кошелёк продуктов банка.

Делаем

Стол RM: досье клиента × новость → ранг → so-what → продукт КИБ → talking points и next action.

Два слоя, не один

  1. Скоринг решает, стоит ли читать. Прозрачная формула, без модели. Жюри может проверить на калькуляторе.
  2. Инсайт пишет so-what. LLM видит досье, новость и кошелёк продуктов. Не пересказ, а разговор RM.

Скоринг не имеет права «придумать» смысл. LLM не имеет права ранжировать ленту. Это сознательное разделение: иначе нельзя объяснить, почему CBAM улетел наверх у Северстали и на дно у X5.

Конвейер

01
Поток. Альфа-Аналитика, регуляторы, котировки, лента. Одна нормализованная карточка: заголовок, лид, теги, тикеры, темы-чувствительности.
02
Контекст. Досье клиента: экспозиции выручки, чувствительности 0–1, конкуренты, география, живые продукты КИБ, ближайшая встреча.
03
Ранг. Формула ниже. Одна новость даёт ~72 для CHMF и ~10 для FIVE.
04
Инсайт. Тип: риск / возможность / событие. Тезис, влияние, горизонт, уверенность.
05
Продукт. DCM, FX, trade finance, ESG-RCF, SCF, гарантии — с формулировкой, не с названием из каталога.
06
Брифинг. Утренний пакет на 4 минуты и повестка встречи с CFO.

2. Архитектура скоринга

Скоринг — пересечение карточки новости и досье, не «семантика всего текста». Темы новости заранее размечены (steel, esg, rates, retail…). У клиента по каждой теме лежит экспозиция от 0 до 1.

score = clip6…97( 10 + T + S1 + S2 + S3 + G + C )
СлагаемоеКогдаВес
БазаВсегда. Новость существует в ленте.10
Тикер TВ карточке прямо стоит CHMF, FIVE, LKOH…+26
Чувствительности SТема новости есть в профиле и экспозиция ≥ 0.35. Берём топ-3 по экспозиции, не по порядку в тексте.e×22, e×12, e×7
Теги GСовпали теги профиля, и чувствительностей меньше двух — чтобы не копить сталь+HRC+export до 99.до +10
Конкурент CНЛМК, Магнит, VK и т.д. в заголовке или лиде.+8

Порядок чувствительностей — по экспозиции клиента. У Северстали сталь всегда бьёт сильнее ставки, даже если в тексте ЦБ упомянут первым. Потолок 97 и пол 6: нет «идеальных 100» и нет нулей, чтобы лента не выглядела мёртвой.

Пример: CBAM × Северсталь

Новость несёт темы esgeusteel и тикер CHMF. Профиль: steel 1.0, esg 0.75, eu 0.7.

База10
Тикер CHMF+26
Сталь 1.00 × 22+22
ESG 0.75 × 12+9
ЕС 0.70 × 7+5
Теги0 (уже три чувствительности)
Итого~72

Та же новость × X5: тикера нет, steel/esg/eu в профиле ритейлера почти нули → ~10. Инфляция 9.1% наоборот: для X5 ~68 (тикер FIVE + retail + rates), для Северстали вторична.

Это и есть демо для жюри: переключили клиента — лента пересобралась, формула читается в чипах «Тикер CHMF · Сталь / HRC · ESG». LLM здесь ещё не участвует.

Что делает модель после скоринга

На вход: досье (экспозиции, продукты, встреча) + текст новости. На выход — JSON: тип, заголовок, тезис, влияние, горизонт, «почему это про вас», продукты с action, talking points, один next step. Промпт запрещает саммари. Запрос только по кнопке, не на загрузке страницы.

3. Команда из пяти

Рекомендованный состав трека КИБ совпадает с командой один в один.

РольЧто сдаёт
Product / UX / BAМодель контекста, карта продуктов КИБ, сценарий RM, критерий «хорошего инсайта».
FrontendСтол: брифинг, лента, досье, смена клиента. Демо 90 секунд без пояснений за кадром.
BackendНормализация потока, API досье, кэш инсайтов.
ML / LLM EngineerРанжирование: тикер, чувствительности, теги, конкуренты.
Prompt EngineerПромпт «новость × компания × продукт». Talking points, не саммари.

Сценарий демо на 90 секунд

  1. Стол Северстали — утренний брифинг, главный сигнал CBAM, продукт ESG-RCF.
  2. Разбор: talking points к встрече с CFO 2 октября.
  3. Та же лента у X5: инфляция и SCF, углерод внизу.
  4. В новости — «собрать инсайт» (живой вызов модели).
  5. «Что сказать CFO про DCM на этой неделе?»

4. Как запустить и выложить

Этот HTML — отдельный статичный концепт. Его можно положить на GitHub Pages или Netlify за пять минут. Полноценный стол RM (React, серверные функции, живой аналитик) — другое: ему нужен Node-хостинг, не «просто Pages».

4.1. Выложить именно этот концепт — GitHub Pages

  1. Создайте репозиторий на GitHub (Public, если нужен открытый URL для жюри).
  2. Положите этот файл в корень репозитория и назовите его index.html. Рядом больше ничего не обязательно.
  3. Commit → Push в ветку main.
  4. Settings репозитория → Pages → Build and deployment → Source: Deploy from a branch.
  5. Branch: main, folder: / (root) → Save.
  6. Через одну–две минуты адрес вида https://.github.io//.

Если файл остаётся concept.html, страница будет по адресу …/concept.html, не с корня. Для жюри удобнее именно index.html.

git init
git add index.html
git commit -m "concept: Альфа Контекст"
git branch -M main
git remote add origin https://github.com/USER/REPO.git
git push -u origin main

4.2. Тот же концепт — Netlify Drop (без git)

  1. На диске создайте папку, внутри только index.html (этот файл).
  2. Откройте app.netlify.com/drop (нужен аккаунт Netlify).
  3. Перетащите папку в окно. Netlify сразу выдаёт URL вида random-name.netlify.app.
  4. Site settings → Domain management → можно переименовать в alfa-kontekst.netlify.app, если имя свободно.

Через git: новый сайт в Netlify → Import from Git → GitHub → выбрать репозиторий. Build command оставьте пустым, publish directory — корень (или папку, где лежит index.html). Для чистого HTML сборка не нужна.

4.3. Локально открыть концепт

Дважды кликните по HTML — откроется в браузере. Сервер не нужен. Шрифты тянутся с Google Fonts, офлайн будет системный шрифт.

4.4. Полное приложение (стол RM) — не Pages

Прототип стола — TanStack Start: серверный рендер и функции «собрать инсайт» / чат аналитика. GitHub Pages это не исполняет (только статика). Netlify из коробки тоже не подхватит текущий Vercel-preset без отдельного адаптера.

Локально у команды:

нужен Node.js 22
npm install
npm run dev

Для кнопки аналитика на сервере должен быть ключ XAI_API_KEY. Без ключа брифинг, лента и досье работают, живой разбор — нет.

Выкладка полного стола:

  1. Залейте исходники в GitHub (весь проект, не только этот HTML).
  2. На vercel.com → Add New Project → Import Git Repository.
  3. Framework подхватится. Env: XAI_API_KEY.
  4. Deploy. Жюри отдаёте URL Vercel.

Netlify для полного приложения: только если переведёте сборку на Netlify Functions / адаптер Nitro. На хакатоне быстрее Vercel или превью, которое уже собрано.

Что отдавать жюри

  • Этот HTML — одностраничник «идея + скоринг + роли».
  • Живой стол — переключение Северсталь / X5 и лента с разными баллами.
  • Не обещать GitHub Pages как хост полного продукта: это хост концепта.

Это статичный концепт. Живой стол RM — в прототипе команды, не на этой странице.
